# Contributing to Timeline Publisher

Thank you for your interest in contributing to Timeline Publisher! We welcome contributions of all kinds: bug reports, feature suggestions, documentation improvements, and code contributions.

## Code of Conduct

Be respectful, inclusive, and constructive in all interactions. We're here to build something great together.

## How to Contribute

### Reporting Bugs

If you find a bug, please open an issue with:

1. **Clear title**: Describe the problem concisely
2. **Steps to reproduce**: Exact steps that trigger the bug
3. **Expected behavior**: What should happen
4. **Actual behavior**: What actually happens
5. **Environment**: macOS version, app version, any relevant details
6. **Screenshots/video**: If applicable, show the problem visually

**Example**:
```
Title: Vignette effect not saving to PNG exports

Steps to reproduce:
1. Enable vignette effect with amount at 60%
2. Select a frame
3. Export as PNG

Expected: PNG includes vignette darkening
Actual: PNG has no vignette effect applied

Environment: macOS 12.5, Timeline Publisher 1.1.0
```

### Suggesting Features

Feature suggestions help us understand what users need. Please:

1. **Check existing issues** — your feature might already be discussed
2. **Describe the use case** — why would this feature be useful?
3. **Show examples** — if possible, reference similar features in other apps
4. **Discuss approach** — if you have thoughts on implementation

### Submitting Code

#### Setup for Development

```bash
# Clone the repository
git clone https://github.com/dougalder/timeline-publisher.git
cd timeline-publisher

# Install dependencies
npm install

# Run web version in browser
open app/index.html

# Or run the Electron app
npm start

# Run tests
npm test
```

#### Before You Code

1. **Create an issue** (or claim an existing one) to discuss your change
2. **Fork the repository** on GitHub
3. **Create a branch**: `git checkout -b feature/description` or `git checkout -b fix/issue-number`
4. **Code with intention**: Follow the existing code style

#### Code Style

- **Indentation**: 2 spaces (never tabs)
- **Variable names**: Descriptive camelCase
- **Comments**: Explain the "why" not the "what"
- **Functions**: Keep them focused and single-purpose
- **Tests**: Add tests for new features and bug fixes

#### Making Your Changes

1. **Make focused commits**: One logical change per commit
2. **Commit messages**: 
   - Start with a verb: "Add", "Fix", "Improve", "Refactor"
   - Be specific: "Fix perspective distortion in 3D labels" not "Fix 3D"
   - Reference issues: "Fixes #123"

3. **Test your changes**:
   - Manual testing: Use the app with various data
   - Automated tests: `npm test` should pass
   - Edge cases: Try extreme values, empty data, large datasets

4. **Update documentation** if needed:
   - Changes to features → update [MANUAL.md](docs/MANUAL.md)
   - New keyboard shortcuts → update [KEYBOARD-SHORTCUTS.md](docs/KEYBOARD-SHORTCUTS.md)
   - API changes → update relevant docs

#### Submitting a Pull Request

1. **Push to your fork**: `git push origin feature/description`
2. **Open a pull request** on GitHub
3. **Fill in the template**:
   - Link to the issue it closes
   - Describe what you changed
   - Explain why this change is needed
   - Note any breaking changes

**Example PR Description**:
```
## Description
Implements perspective-correct label rendering in 3D mode.

## Issue
Closes #45

## Changes
- Added perspectiveScale() calculation for distance-based scaling
- Implemented collision detection to prevent label overlap
- Labels now render upright (not tilted with the timeline)

## Testing
- Manual testing with various timeline sizes
- All existing e2e tests pass
- New test: 3D label positioning under various camera angles

## Breaking Changes
None
```

## Development Workflow Details

### Project Structure

```
timeline-publisher/
├── app/                    # Web application (HTML, CSS, JS)
│   ├── index.html         # Main UI and all scripts
│   └── sample-data.json   # Sample timeline for demos
├── build/                 # Build assets
│   └── icon.icns         # App icon for macOS
├── out/                   # Built app (generated by build script)
├── tests/                 # Test files
│   ├── e2e.mjs          # End-to-end tests
│   └── run.sh           # Test runner script
├── main.js              # Electron main process
├── preload.js           # Electron preload script
├── build.mjs            # Build script
├── pack-mac.sh          # macOS packaging script
├── package.json         # Dependencies and scripts
└── README.md            # This file
```

### Key Files to Understand

**`app/index.html`** — The entire application:
- UI layout and styling
- All interactive controls
- Timeline rendering logic
- 3D visualization and camera
- Data table editor
- Video export pipeline
- CSV import/export

**`main.js`** — Electron app shell:
- Window creation and lifecycle
- Menu bar implementation
- File dialogs and downloads
- IPC bridge to web content
- Window state persistence

**`preload.js`** — Security bridge:
- Exposes tpDesktop object to page
- Handles file reveal (Show in Finder)
- No file system access for the page

**`tests/e2e.mjs`** — Comprehensive tests:
- Tests all major features
- Verifies file I/O
- Checks visual effects
- Validates exports

### Testing

Run tests with:
```bash
npm test
```

Tests use Playwright and Electron to verify:
- App launches and displays correctly
- Menu commands work
- CSV import functions
- Data editing persists
- 3D mode renders with WebGL
- PNG/video exports create valid files
- Projects save/load correctly
- Unsaved changes prompt appears
- Published web pages work in browsers

Add new tests in `tests/e2e.mjs` following the pattern:
```javascript
ok('feature description', condition, info);
```

The `ok()` function logs results and tracks failures.

### Building for Distribution

The macOS app is built and signed with:
```bash
bash pack-mac.sh
```

This:
1. Packages the app with electron-packager
2. Strips non-English language packs
3. Signs with ad-hoc code signature
4. Creates a distributable `.dmg`

### Performance Considerations

When modifying code, keep these in mind:

- **Rendering**: Timeline pan/zoom should stay smooth (60 FPS)
- **Large data**: Handle timelines with 1000+ events gracefully
- **Memory**: Avoid keeping large canvases in memory unnecessarily
- **3D rendering**: WebGL optimizations are critical for performance
- **Exports**: Video encoding can be slow (it's normal)
